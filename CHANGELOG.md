## [0.1.0](https://github.com/DennisPohlmann/gameWE-collector/compare/v0.0.0...v0.1.0) (2026-10-23)

### Features

* first public release v0.1.0 ([b41b20a](https://github.com/DennisPohlmann/gameWE-collector/commit/b41b20a0feb64665d9acd8c837b274bd69a45819))

The first public release. gameWE - collector is a fork of HLstatsX:CE: it
replaces the Perl daemon (`hlstats.pl`) and its helper scripts with one static
Go binary `gamewe` and writes into the same kind of HLstatsX database (the
gameME-style variant), so HLstatsX web pages and other readers keep working.
The entries below describe 0.1.0 compared to HLstatsX:CE.

### Added

- **Collector** (`gamewe run`): a UDP log receiver for many game servers at
  once (`logaddress_add`), default port 41337. Only servers registered in
  `hlstats_Servers` (address and game port) are accepted; every server has its
  own worker, bounded queue and player state. Every received line can be
  written to the journal (`gamewe_log_lines`, control characters escaped).
- **Engines:** Source (CS:S, CS:GO, TF2, DoD:S, HL2:DM, L4D, L4D2,
  Insurgency) and GoldSrc (CS 1.6, DoD, TFC, HL1, NS: UDP challenge RCON,
  HLDS `status`, AMX Mod X plugin replies). `hlstats_Games.realgame` picks the
  engine; a ranking cloned from a game (`css1`, `css3`, ...) uses only its own
  rows, an empty or unknown realgame is guessed from the code.
- **PostgreSQL** (`database.type: postgres`) besides MariaDB / MySQL:
  `schema/postgres/`, generated from the MariaDB schema by `tools/schemagen`
  (`make schema`) with the same tables, columns, defaults and reference data.
  The collector writes portable SQL and the same values into both; it
  computes `yearweek_id` itself (MySQL `YEARWEEK` mode 0).
- **Database setup** in one step: `schema/init/init-db.sh` (MariaDB) and
  `schema/postgres/init/init-db.sh` create the database, the users `gamewe`
  (collector), `gamewe_web` (public pages) and `gamewe_web_admin` (admin
  pages), the complete schema, the reference data and the rights.
  `02_seed.sql` only inserts missing rows and can be run again at any time.
- **Complete reference data for every base game**, from HLstatsX:CE and, for
  CS:S, the gameME values: teams, roles, actions with rewards, weapons with
  modifiers, awards, ranks and ribbons with bronze / silver / gold classes for
  all games (also insurgency, l4d, l4d2), the game-independent daily awards
  (most kills, deaths, suicides, headshots, damage, most improved, longest
  play time, longest kill streak, best latency), GunGame actions for css, and
  for CS:GO the 15 roles of the SourceMod plugin, the kill-flag, assist and
  accolade actions and the weapons CE lacks (`incgrenade`, `healthshot`,
  `knifegg`, `tagrenade`, Danger Zone weapons, `c4`, `planted_c4`, `world`, ...).
- **CS:GO:** kill positions, the kill flags penetrated, noscope, throughsmoke
  and attackerblind as actions `kill_<flag>`, kill assists and flash assists
  (`flash_assist`), bomb deaths (weapon `planted_c4`), end-of-match accolades
  (`accolade_<name>`), round MVPs (docs/GAMES.md).
- **Kill positions for heatmaps:** `hlstats_Events_Frags.pos_x/y/z` (killer)
  and `pos_victim_x/y/z` (victim), from the kill line or the plugin's
  `located on "kill"` line, which may come before or after the kill; also in
  `hlstats_Events_Locations` (`gamewe_store_locations`).
- `server_id` (= `hlstats_Servers.serverId`) in `hlstats_Events_Frags`,
  `_Teamkills`, `_Suicides`, `_PlayerActions`, `_PlayerPlayerActions`,
  `_TeamBonuses`, `_Entries`, `_Disconnects` and `_ChangeTeam`, as in
  `_Chat` and `_Latency`, with an index `(server_id, timestamp_id)`.
- **More statistics** for the web: kill assists (CS:GO, TF2),
  survived rounds (`survived_count`, `survived`), time, rounds, wins, losses
  and survived rounds per team and role (`hlstats_Teams`, `hlstats_Roles`,
  stored every minute), connect methods (`connect_type` from
  `cl_connectmethod`), ping samples per player and minute
  (`hlstats_Events_Latency`, kept 90 days) with the running average ping,
  and rounds, wins and losses per day in `hlstats_Players_History`.
- **Daily awards** inside the collector (no cron script): at a configured
  time and IANA time zone (`features.daily_awards`, default 00:00 UTC) the
  previous day's awards go into `hlstats_Awards_History` and
  `hlstats_Awards.d_winner_*`; `gamewe awards -date YYYY-MM-DD` decides a day
  again. Indexes on `hlstats_Awards_History` for the awards page.
- **Ranking resets while the collector runs:** the web admin or `gamewe reset
  GAME -mode stats|all [-dry-run]` queue a job in `hlstats_gamewe_jobs`; the
  collector pauses the servers of that game, resets, clears the live view and
  reports rows per table. Without a running collector (heartbeat in
  `hlstats_Options` `gamewe_heartbeat`) `gamewe reset` resets directly.
- **RCON jobs** per server (`features:` in the config): `status` every 10
  seconds over one connection that stays open (live view, `act_players`, map,
  `max_players`, pings, also on an empty server and after a restart), log
  address check every minute (`logaddress_list`, registers the collector again
  with `logaddress_add` and `log on`), server load.
- **GeoIP:** player and server locations from a MaxMind-format city database.
  The DB-IP City Lite database (CC BY 4.0) is bundled
  (`/var/lib/gamewe/collector/dbip-city-lite.mmdb`) and updated monthly by the
  collector (`geoip.auto_update`, `gamewe geoip-update`); a replaced file is
  used within 10 minutes. MaxMind GeoLite2 works with `geoip.path`.
- **In-game commands** `!rank`, `!statsme`, `!session`, `!status`, `!next`,
  `!top10`, `!hideranking [1|0]`, `!settings` and `!help` (`!` or `/`), shown
  as a gameME-style panel, as chat lines or both (`gamewe_command_display`).
- **gameME / gameWE plugin interface:** answers to other plugins' queries
  (`playerinfo`, `top10`, `next`, `spectatorinfo` as `gamewe_raw_message`
  101 / 102 / 103 / 1001), raw messages for the chat commands
  (`gamewe_raw_messages`), `gamewe_command_prefix` `gameme` for servers with
  the original gameME plugin, `weaponstats` / `weaponstats2`, player models,
  `mvp` and `clantag` triggers.
- **Command line:** `gamewe check` (config, database and TLS, schema
  completeness, servers, settings), `status`, `logaddress`, `rcon`, `game`,
  `server`, `option` (like the web admin, with `-dry-run`; RCON passwords from
  a file or stdin, never printed), `reset`, `awards`, `geoip-update`,
  `simulate` (replays a sample game into the database or to a running
  collector) and `-V` / `version`.
- **Packaging:** release archive `gamewe-collector-<version>-linux-amd64.tar.gz`
  (a tree for `/` with a `.sha256` file), hardened systemd unit
  `gamewe-collector.service`, Arch Linux `PKGBUILD`, the container image
  `ghcr.io/dennispohlmann/gamewe-collector` (distroless, non-root) and
  `docker-compose.example.yml` with an optional MariaDB or PostgreSQL.
- `THIRD-PARTY-LICENSES.md` and `licenses/`: every Go module compiled into
  `gamewe`, the bundled DB-IP database and the image base images, with their
  license texts; a test fails if a compiled module is missing.
- Tests: unit tests per log format, fuzz tests of the parsers, integration
  tests against MariaDB 11.4 / 12.3 and PostgreSQL 17 / 18 (both init scripts,
  rights of the web users, schema comparison of both databases).

### Changed

- **Configuration:** the YAML file (`/etc/gamewe/collector/config.yaml`)
  holds only `listen`, `database` (with `password_file` and TLS), `geoip` and
  `features`. Game servers with their `rcon_password` come from
  `hlstats_Servers` (new column), points and switches from `hlstats_Options`
  keys `gamewe_*` with built-in defaults; both are re-read every minute, so
  the web admin changes them without a restart.
- **Database TLS** modes `disable` (default), `require`, `verify-ca` and
  `verify-full`, with CA, client certificate and `server_name`; never a
  plaintext fallback when a mode is set.
- Schema and connection are **utf8mb4** (`utf8mb4_unicode_ci`); the live view
  is written with one upsert per row.
- Bots are always recorded (live view, `act_players`, their own statistics);
  `gamewe_rank_bots` (default 0) decides whether they are ranked and whether
  kills with bots change anybody's skill.
- Player IPs and chat are stored by default (`gamewe_store_player_ip`,
  `gamewe_store_chat`), readable only by `gamewe_web_admin`.
- The live view and `act_players` follow reality: a map change ends all
  visits of the server, visits without a logged disconnect end after
  `gamewe_idle_timeout` (bots after 3 minutes), never more players than
  `max_players` are counted, an RCON status answered after a map change is
  ignored, and a server registered twice (every line sent twice) is detected.
- `hideranking` 3 means hidden by the player (`!hideranking`), not inactive.

### Removed

- The Perl daemon and scripts of HLstatsX:CE (`hlstats.pl`, the awards and
  resolve scripts, `hlstats.conf`, `hlstats_Games_Defaults`). The web
  frontend is not part of the collector.
- Log secrets (`sv_logsecret`): the server list decides who may send.
- LAN ids (`VALVE_ID_LAN`, ...) are not tracked.
- Counter-Strike 2 is not supported: it sends no UDP logs and SourceMod does
  not run on it.
- Schema migrations: a database is always created new from `schema/init/`;
  `gamewe check` and the collector's start report missing columns
  (`schema incomplete: missing <table.column>`), and the collector keeps
  running without them.

### Fixed

- CS:GO awards and ribbons: CE's codes `firebomb`, `sg553` and `round_mvp`
  never matched the logged weapons `inferno`, `sg556` and the plugin's
  trigger `mvp`.

### Security

- `gamewe_web` (public pages) has SELECT only and cannot read `hlstats_Users`,
  `hlstats_Events_Rcon`, `hlstats_Events_Chat`,
  `hlstats_Servers.rcon_password` and `hlstats_Events_Connects.ipAddress`
  (column rights, MariaDB and PostgreSQL); `gamewe_web_admin` writes only
  settings, definitions, servers, admin users, the skill / hideranking / clan
  of players and ranking jobs; the collector user never changes the
  structure.
- Every SQL statement uses placeholders. Log lines are accepted only from
  registered servers; text sent back over RCON is sanitized (no quotes,
  semicolons or control characters, bounded length); queues and per-source
  state are bounded.
- Passwords, RCON passwords and the database DSN are never logged or
  printed. A warning banner when the collector runs as root.
- The systemd unit runs as user `gamewe` with hardening options; the image
  runs as `nonroot` on distroless. The GeoIP download is size-limited,
  checked and replaces the file atomically. CI runs govulncheck.

### Known limitations

- The TLS modes have not been tested against a live database server.
- `gamewe_csay`, `gamewe_tsay`, `gamewe_hint`, `gamewe_khint` and
  `gamewe_browse` are not used by any command yet; the plugin menu commands
  `/clans`, `/weapons`, `/accuracy`, `/targets`, `/kills`, `/cheaters`,
  `/gamewe_reset`, `/gamewe_auto`, `/gamewe_display` and `/gamewe_chat` are
  ignored.
- Not filled: per-team and per-map player statistics
  (`hlstats_Players_Teams*`, `_Maps*`), monthly histories, `rank` /
  `sort_skill`, trends, `hlstats_Maps.teama_wins` / `teamb_wins`; team scores
  (`Team "x" scored`) have no table and are ignored (docs/DB-SEMANTICS.md).
- Log lines received while the database is unreachable are dropped once the
  in-memory queue is full; there is no on-disk buffer.
- `03_grants.sql` uses MariaDB syntax and does not run on MySQL.
