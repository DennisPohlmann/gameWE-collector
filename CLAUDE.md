# gameWE collector - notes for Claude

Go daemon (`module gamewe-collector`, Go 1.27) that receives Source engine
log lines over UDP, parses them (`internal/logparse`), writes stats into the
HLstatsX/gameME schema on MariaDB/MySQL or PostgreSQL (`internal/stats`,
`internal/database`) and answers in-game commands over RCON
(`internal/rcon`, `internal/collector/reply.go`). Config: YAML
(`config.example.yaml`, installed as `/etc/gamewe/collector/config.yaml`),
game servers and their `rcon_password` live in `hlstats_Servers`.

Build and test: `make` (vet + test + build), `go test ./...`, integration
tests need a database (`-tags integration`, see `.github/workflows/build.yml`).

Releases: Conventional Commits + semantic-release (`.releaserc.json`). Every
push to `main` is built and tested and the image is published as
`ghcr.io/dennispohlmann/gamewe-collector:edge`; `feat`/`fix`/breaking
commits make semantic-release bump the version files, write `CHANGELOG.md`,
commit `chore(release): vX.Y.Z [skip ci]`, tag `vX.Y.Z` and publish the
GitHub release with the archive (+ sha256) and the image tags `<version>`,
`<major>.<minor>`, `latest`. There is no tag-triggered workflow.

   run the `security-check` skill on the diff and fix what it finds. Say in

   releases are made by semantic-release in CI when `feat`, `fix` or

   `vX.Y.Z`, GitHub release). Before pushing such commits to `main`, run
   the `release-security-gate` skill over the whole repo, without asking
   first. Never tag by hand or edit version files / `CHANGELOG.md`; report
   the gate result and ask Dennis for the go before the push.
3. A finding you cannot fix in scope goes into the answer with file:line,
   impact and a proposed fix. Never silence a check, skip a test or weaken

## Before every commit (mandatory, standing rule from Dennis)

Run the `pre-commit-checklist` skill before every `git commit`, together
with `security-check`, also for small fixes:

1. Check `README.md` (and `INSTALLATION.md`) against the change and update
   it in the same commit.
2. Write the commit message as a Conventional Commit (`feat:`, `fix:`,
   `docs:`, ... see the `pre-commit-checklist` skill). `CHANGELOG.md` and
   the version files are generated by semantic-release; never edit them.
3. Check dependencies and toolchain for updates and *suggest* available
   updates (do not update on your own).
4. Check the licenses of third-party code and keep the license list
   complete and current.

Report the result of each step in one line in your answer.

## Invariants that must not break

- Every SQL statement uses placeholders (`?`, rebound for Postgres in
  `internal/database/rebind.go`). Table/column names in `fmt.Sprintf` SQL
  only from constants or a fixed allowlist, never from log or RCON data.
- Log packets are accepted only from addresses in `hlstats_Servers`
  (no log secret support): treat every field of a log line (player names,
  chat, weapons, map, team, SteamIDs) as attacker-controlled input.
- Text going back to a game server over RCON passes `Sanitize`
  (`internal/collector/commands.go`) or `quoted` (`rawmessage.go`):
  no `"`, `;`, control characters, bounded length.
- Bounded memory under floods: maps keyed by source/player are capped
  (see `ServeConn` in `udp.go`), queues are bounded and drop instead of
  blocking (`RconReplier`).
- Never log passwords, RCON passwords, the DB DSN or full config.
- DB users: the collector user writes, `gamewe_web` gets SELECT only and
  no `hlstats_Users`, `hlstats_Events_Rcon`, `hlstats_Events_Chat`,
  `hlstats_Servers.rcon_password`, `hlstats_Events_Connects.ipAddress`
  (`schema/init/03_grants.sql` and the Postgres counterpart). A new table
  needs a grant decision in both files (a test checks this).
- Secrets stay out of git: `config.yaml`, `*.pem`, `*.key`, real
  `docker-compose.yml` values are ignored; examples use `change-me`.
